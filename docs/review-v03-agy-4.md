   - **Failure scenario:** When [`NativeEngine::merge_observed`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-ffi/src/storage_engine.rs#L309-L348) receives a batch that contains both (a) a new `authority/` record with an unsealed epoch key for `self.library.me` and (b) an already-listed immutable record whose provider content version changed (`changed_version == true`), `Self::merge_locked` calls `s.engine.apply_paths`, which runs `self.reset("Authority listing changed")` and sets `self.ready = false` ([`storage.rs:818-820`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-core/src/storage.rs#L818-L820)) so content replay waits for host ECDH. Immediately afterward, line 340 executes `if changed_version { let changes = s.engine.refresh(listing)?; ... }` before the host has a chance to call `ready()` / `finish_unlock_many`, causing [`Engine::refresh`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-core/src/storage.rs#L615) to fail in `check_ready()` with `"Engine requires finish_unlock_many before use"`.
   - **Fix:** Guard the `if changed_version` refresh in [`NativeEngine::merge_observed`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-ffi/src/storage_engine.rs#L338) with `if changed_version && s.engine.begin_unlock().is_empty()` (or skip it whenever `merge_locked` already triggered an authority reset, which already cleared `self.entries` and queued `self.listing` with the updated provider versions).

2. **[`crates/colophon-core/src/storage.rs:1009`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-core/src/storage.rs#L1009), [`crates/colophon-core/src/storage.rs:1087`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-core/src/storage.rs#L1087), [`crates/colophon-core/src/storage.rs:1155-1201`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-core/src/storage.rs#L1155-L1201) — Low**
   - **Failure scenario:** In [`Engine::process_pending`](file:///Users/mikelxc/projects/colophon-wt/engine-sessions/crates/colophon-core/src/storage.rs#L927-L1214), if a replaceable `state/` slot first fails header/signature verification (inserting into `self.rejections` at line 1009) and is later replaced at the same path by a valid `state/` record without an authority reset, `self.rejections.remove(*path)` is not called, leaving the stale rejection in `self.rejections`.
