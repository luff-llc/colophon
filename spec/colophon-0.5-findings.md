# Colophon 0.5 W1 slice 1 — specification findings

**Source:** Galley `docs/spec/colophon-0.5-draft.md`, draft 1, 2026-11-10.
**Status:** implementation readings for review, **not** amendments to the specification.
**Scope:** §1, §5, §6. The 0.4 implementation is deliberately unchanged.

| Section | Problem | Reading implemented in this slice | Alternative requiring a specification decision |
| --- | --- | --- | --- |
| §5.2 | `links:["<envelope>"]` doesn't say how a JSON envelope is represented inside a JSON string. | Each item is **standard padded base64 of the canonical JSON envelope bytes**, and that envelope contains base64 body/signature, as in the existing record encoding. The proof's digest covers these encoded strings. | Embed envelope objects directly; or embed raw JSON strings. This changes proof digests and must be frozen before shipping. |
| §1, §5.2 | 0.4's parser decodes standard base64 but does not explicitly require re-encoding equality. | New link, proof and request parsers reject noncanonical base64 spellings; canonical writer always emits padded standard base64. | Accept any `STANDARD.decode` spelling for wire parity with 0.4 and preserve the original text verbatim for digests. |
| §5.3, §1 | “Unknown only after signatures” conflicts with six-step order: request signature/possession is step 6 but checking unknown link terms follows step 3. | Verify **all** link signatures, then preverify the raw request signature, before returning `newerFormat`. Verify binding/possession at step 6. An invalid request must not force an update prompt. | Authenticate only links before unknown-term detection; then unsigned/copyable proofs could force `newerFormat` without possession. |
| §5.3 step 1 | “Fetch from homes” is not a pure operation. | `VerifiedHistory::contains` signals whether the exact verified sequence/digest is present; absent returns `refused:stale`. Host fetches/retries outside core. | Inject a fetch callback, making the check dependent on external IO. |
| §5.3 step 2 | “grant expiry” and optional `terms.expires` may be distinct and can conflict. | Both are inclusive, with the earlier as the effective expiry; a revoked/missing member returns `refused:revoked`. | Define one canonical field and remove redundant expiry from the history interface. |
| §5.3 step 3 | `account`/`from` mismatches, malformed point, excessive links and temporal errors have no precise error mapping. | Wrong signed chain identity is `badSignature`; malformed point/envelope and >8 links are `malformed`; future/not-yet-active or past link is `refused:expired`. | Classify mismatched account as `refused:outOfScope` and mismatched `from` as `malformed`. |
| §5.3 step 3, §6.2 | A link that outlives its parent's envelope expiry is prohibited but not explicitly one of the narrowing rules. | Treat later expiry than any parent link/grant as `refused:notNarrower`; depth exhaustion also yields `refused:notNarrower`. | Return `refused:expired` for parent-lifetime violations; introduce a separate `refused:depthExceeded` code. |
| §5.1, §5.3 step 4 | First-link `session` presence is specified, but member-only proofs and later links are not explicit. | Require session on exactly the **first** link when links exist; later links must omit it. No-link proofs have no session to compare. If guarded state isn't available, report `ok` with `unguarded: true` even with no links. | Permit optional first-link session for unguarded readers, or report unguarded only when a session link exists. |
| §5.3 | The proof's `asOf` binds the authority prefix but member state is explicitly checked against “latest history it holds.” An older verified prefix may allow different authorizations. | Require `asOf` exact digest present; look up current member state in latest verified local history, rather than freezing member terms at `asOf`. | Replay and evaluate all terms as of `asOf` (but permits grants revoked later). |
| §5.5 | The draft has no result codes for wrong audience, bad request digest, replay, and a request older than 300 seconds. | Audience, request body/proof/purpose mismatch and seen nonce return `refused:outOfScope`; timestamp outside ±300 seconds returns `refused:expired`; bad request signature returns `badSignature`. | Introduce separate `refused:replay`, `refused:audience`, `refused:requestExpired` codes. |
| §5.5 | `body` says only “digest of what is asked”; it doesn't specify whether it covers canonical JSON, raw bytes, a transition, or an operation ID. | Caller supplies a previously computed **64-hex SHA-256 digest** of its exact requested body; core checks equality. | Make `check` receive canonical request-body bytes and compute the digest itself; standardize the body format. |
| §5.5, §15.2 | Nonce cache key, storage, window and replay policy aren't defined; offline pending (§8.4) explicitly permits longer windows. | Caller supplies a nonce-seen callback and manages its own 300-second cache; no IO/storage in core. Only online 300-second requests are implemented. | Define cache key tuple, durable replay ledger and offline `guard.pendingMaxAge` integration. |
| §6.1, article 4.4 | “Bounded, printable” does not specify lengths for namespace/kind/capability/path names or maximum term size beyond conditions. | Reject empty, control-character or >256-byte individual names/paths. Restrict scope to 1–64 entries, conditions to 4,096 bytes, 32 predicates, depth 4. No invented overall terms-byte limit. | Define separate byte limits and a Unicode normalization profile; impose an explicit cap on the whole terms object. |
| §6.1 | Duplicate entries, sorting and empty optional arrays are unspecified. | Reject duplicate items within `kinds`, `requires` and `serves`; permit empty optional `requires`, `serves` and `conditions` arrays. | Require sorted distinct arrays like 0.4 controller IDs, or treat lists as sets and normalize. |
| §6.1, §6.3 | `requires` may name future capabilities, but no extensible verifier registry is specified, and raw ES256 request signatures cannot demonstrate WebAuthn UV alone. | `uv` is the only known capability. The host supplies a **trusted `uv` attestation bit** to the pure check, and unknown capabilities return authenticated `newerFormat`. | Add typed evidence to requests or explicit per-key capability proofs; add a verifier extension registry. |
| §6.2 | Omitting `expires` and `writes` is not explicitly defined under narrowing. | Absent is unbounded, so a bounded parent cannot delegate an omitted child bound; an unbounded parent can delegate either. | Require every delegated link to spell out expiry and write allowance. |
| §6.2 | “conditions include all of A's” doesn't define syntactic inclusion versus semantic implication (`lte 5` is narrower than `lte 10`). | Require exact JSON equality for each inherited condition; allow additions, not rewriting or algebraic simplification. `requires` and `serves` are set inclusion. | Define a semantic implication checker or a normalized predicate algebra. |
| §6.3 | `guard:<kind>` has no namespace/access mapping, and `colophon.sign`/`publish` are privileged but have no scoped representation examples. | `guard:<kind>` requires **write** access in namespace `colophon` with an explicit kind `guard:<kind>`; `colophon.sign` and `colophon.publish` require explicit `sign`/`publish` (or full-name) kind in `colophon` scope. An unrestricted `kinds` field alone is not sufficient for these special purposes. | Give guard a separate scope grammar and dedicated purpose entries; distinguish controller-owned-key exceptions in §3.1. |
| §6.5 | `args.amount` path convention leaves unclear whether caller supplies `{"args": ...}` or the arguments object itself; missing paths and empty `all`/`any` undefined. | Paths starting `args.` navigate directly into the supplied arguments; bare paths also work. Missing path is false. Empty `all` is true and empty `any` is false. | Require explicit `args` root and disallow empty logical collections. |
| §6.5 | Numeric comparison of integers vs floats is underspecified. Converting all JSON numbers to binary64 could conflate distinct signed/unsigned 64-bit integers beyond 2^53 and incorrectly authorize an over-limit action. | `lte`/`gte` compare integer-token values exactly as i128, compare finite float tokens with IEEE-754 semantics, and compare mixed int/float values without lossy int-to-f64 casts. `eq` uses JSON structural equality. Includes a regression test at 2^53 and 2^53+1. | Explicitly restrict numbers to the exact binary64 integer range, define decimal semantics, or provide an arbitrary-precision format for financial quantities. |
| §6.5 | Does maximum nesting include the first predicate and do composite nodes count toward 32? | Root predicate is depth 1; `all`, `any` and `not` each count as a predicate. Bounds are inclusive. Canonical conditions array at 4,096 bytes is accepted; 4,097 refused `malformed`. | Count only leaf predicates, or depth from zero. |
| §15.1, §15.3–7 | The draft itself flags propose/read coupling, `keptThrough` monotonicity, self-contained-history bloat, fuel portability, floating point and pre-rotation. | Not implemented in this slice; no interpretation was silently adopted. | Resolve through W2–W5 and further design review. |

## Measurement / validation

- A deterministic synthetic fixture generator and a native disk-only reader are provided. Fixtures use `SoftwareKeys::from_seed([n;32])` and are never production secrets.
- Verification of a three-link proof should be timed with a native release build before freezing performance claims. **No three-link latency measurement is asserted here.**
- No dependency additions. Reuses `p256`, `serde_json`, `base64` and the existing Colophon modules.
